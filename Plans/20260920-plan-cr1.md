# Plan: Event, Attendance, And Custom Field Improvements

## Goal

Improve daily church operations by making event setup clearer, adding church-scoped custom-field administration, making occurrence management intentional, and allowing staff to reverse accidental check-ins without destroying audit history.

## Decisions

- Birth dates remain ISO date-only values in the API, while controls use US-friendly presentation.
- New events begin with blank date, time, and time-zone values; existing immutable schedule values remain visible.
- Time-zone choices are US zones plus UTC, stored as IANA identifiers.
- Deleting an occurrence means cancelling it. Cancelled occurrences retain history, are hidden from normal Check-In selection, and can be restored while future-dated.
- Each Generate action creates only the earliest missing upcoming occurrence.
- Undo check-in is an auditable soft void rather than a destructive deletion. Authentication and server-enforced authorization remain production prerequisites.
- Custom fields are administered per church from Settings. Field type is immutable after creation; archiving preserves historical member values.

## Implementation

1. Update shared mobile date and time controls in `src/JcChurchMobile/src/ui.tsx`. Keep ISO `yyyy-MM-dd` and `yyyy-MM-ddTHH:mm` values internally, present US-friendly dates and times, and support date-only and time-only fields.
2. Refactor event draft validation in `src/JcChurchMobile/src/domain.ts` and `src/JcChurchMobile/src/screens/Events.tsx`. Store date and time separately in the UI, require both for new events, combine them into `localStart` on save, and preserve existing DST and year validation.
3. Replace the event time-zone text field with a US-zone `Select` using friendly labels and IANA values. Do not infer a default time zone for new events.
4. Add a recurrence formatter in `domain.ts` and use it in event rows and the Event & sessions detail view. Render supported RRULE values as plain language instead of raw syntax.
5. Change `EventService.Generate` to create the earliest missing upcoming occurrence once per call. Update the occurrence-generation response contract, regenerate mobile API types, and change the event screen feedback to singular language.
6. Improve future occurrence cancellation in `Events.tsx`: use a destructive confirmed Cancel occurrence action, retain the existing restore path, hide cancelled sessions from check-in selection, and retain them on the Event screen for review.
7. Add an attendance soft-void and immutable audit model across domain, storage, check-in service, HTTP dispatch, and OpenAPI. Create an idempotent occurrence/member undo endpoint. Active reports and status responses must exclude voided receipts; a subsequent check-in must create a new active receipt state while preserving the audit trail.
8. Update `CheckIn.tsx` and `api/client.ts`: replace the Checked In UTC-date filter with member-name search, add a confirmed per-receipt Undo action, invalidate relevant queries, and preserve existing retry/recovery behavior.
9. Improve manual check-in rows: place a compact Check In action beside the member name and show age, school, and groups underneath when available.
10. Add church-scoped custom-field management in Settings. Add a Manage custom fields entry beside Manage groups in `Churches.tsx`, a hidden church route, and a `CustomFields.tsx` management screen based on the existing Groups patterns. Support create, rename, archive, active/archived listing, stale-edit recovery, and create-time Text, Number, Yes/No, and Date types. Invalidate member-form definition queries after changes.
11. Extend backend, client, and browser tests for form behavior, recurrence presentation, single generation, cancellation/restore, attendance reversal/re-check-in, checked-in search, compact member metadata, and custom-field administration.

## Verification

2. Regenerate mobile API types, then run `npm --prefix src/JcChurchMobile run typecheck` and `npm --prefix src/JcChurchMobile test`.
3. Start the local Functions host and Expo preview, then run `npm --prefix src/JcChurchMobile run test:e2e`.
4. Verify native iOS and Android picker, cancellation, check-in undo, and custom-field administration behavior on physical devices before release.

## Scope Boundaries

- No recurrence-editor redesign beyond friendly rendering of supported rules.
- No destructive occurrence or attendance deletion.
- No offline write queue, bulk session generation, or authentication system implementation.
