# Plan: Clarify Event Sessions

## Goal

Make the Event & sessions screen easier to scan by removing redundant labels, adding clear session status and active check-in counts, supporting reversible archival of completed sessions, and allowing staff to reverse the date order of the single session list.

## Decisions

- Remove the standalone `Sessions` heading and raw IANA time-zone label beneath `Save event`.
- Keep one session list with badges instead of collapsible date groups.
- Add a local `Date order` select: `Soonest first` by default and `Latest first` as the reverse option.
- `Archived` is a new, reversible occurrence state for ended sessions; it is distinct from cancellation and event archival.
- Check-in counts represent active check-ins only. Undo decreases the count; re-check-in restores it.
- Derive counts server-side in one event-scoped aggregate query rather than persisting mutable counters on occurrences.

## Implementation

1. Extend `Occurrence` in `src/jchurchFunction/Domain/Documents.cs` with a server-managed `Archived` boolean. Existing documents deserialize as `false`, preserving backward compatibility.

2. Update the occurrence override request and dispatch in `src/jchurchFunction/Functions/ChurchApi.cs` to accept `archived`. In `src/jchurchFunction/Services/EventService.cs`, use the injected clock to allow archive/restore only after `EndsAt`. Archive-only updates cannot modify timing or cancellation; timing and cancellation retain their current future-only rules. Continue using ETags for all changes.

3. Add a read-only repository aggregation that returns active attendance totals keyed by occurrence ID for one event. Implement it in `src/jchurchFunction/Storage/InMemoryRepository.cs` and `src/jchurchFunction/Storage/CosmosRepository.cs`. Cosmos should use one parameterized `GROUP BY occurrenceId` query scoped to church and event, filtering `kind = 'Attendance'` and `active = true`.

4. Add `GET /churches/{churchId}/events/{eventId}/occurrence-check-in-counts`, returning records such as `{ occurrenceId, checkedInCount }`. Missing records imply zero. Update `src/jchurchFunction/openapi.json` and regenerate `src/JcChurchMobile/src/api/generated.ts`.

5. Refactor `SessionList` in `src/JcChurchMobile/src/screens/Events.tsx` to load occurrences and their count map together. Remove the redundant heading/time-zone label. Keep one list, add the date-order select, and sort the already-visible sessions locally without changing server pagination.

6. Classify rows in the event timezone: `Today` when the local start date is today, `Upcoming` when the session starts later, and `Past` when it has ended. Combine this with lifecycle badges (`Archived`, `Cancelled`, `Rescheduled`) deterministically, with `Archived` first when multiple states apply. Show active count text for each session.

7. Add Archive session and Restore archived session controls to Session details. Require confirmation. Archive is permitted only for ended sessions. Archived and cancelled sessions remain visible in Event & sessions but cannot be selected for normal check-in.

8. Invalidate occurrence-list and count-summary queries after manual/scan check-in, undo, cancellation/restore, archive/restore, and generation. Follow the existing TanStack Query key conventions.

9. Add focused tests:
   - Backend service/repository tests for archive eligibility, restore, invalid state transitions, and active-only count changes across check-in, undo, and re-check-in.
   - HTTP smoke coverage for the summary endpoint and archive lifecycle.
   - Mobile unit and E2E coverage for omitted labels, default/reversed date order, status badges, count updates, archive/restore, and check-in exclusion.
