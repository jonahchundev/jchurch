# Plan: Session Cancellation, Time Zones, And Date/Time Pickers

## Goal

Resolve session cancellation feedback, clarify cancelled occurrence status, display friendly names for all configured time zones, and make browser date/time fields use platform picker controls while preserving Expo native picker behavior.

## Decisions

- A cancellation confirmation remains available if the save fails, but is dismissed after the API confirms the cancellation.
- `Cancelled` is a terminal list status: it suppresses `Rescheduled`, `Today`, `Past`, and `Upcoming` for that occurrence.
- Cancelled status uses the existing danger color, visually separating it from active session states.
- Configured US time zones and UTC display their friendly option labels without the parenthesized IANA identifier. Unknown zones display their persisted IANA identifier.
- iOS and Android continue using `@react-native-community/datetimepicker`.
- Browser preview uses native HTML `date`, `time`, and `datetime-local` inputs through the Expo React Native Web layer; form values remain ISO strings.

## Implementation

1. Add `timeZoneLabel` in `src/JcChurchMobile/src/domain.ts`. It will derive friendly display text from the existing `usTimeZones` option list, removing the IANA ID in parentheses while falling back to the supplied value for a zone not in that list.

2. Update `SessionEditor` in `src/JcChurchMobile/src/screens/Events.tsx` so a successful `save` closes the cancellation confirmation. Keep it open after a failed mutation, enabling a retry or explicit cancellation of the dialog.

3. Refactor `SessionList` status calculation so `cancelled` produces only `Cancelled`. Keep current behavior for non-cancelled rows. Supply a danger badge variant for cancellation and use `timeZoneLabel` in the row subtitle.

4. Extend `Row` in `src/JcChurchMobile/src/ui.tsx` with a narrow badge variant API. Add a danger style without changing existing row consumers.

5. In the `Platform.OS === "web"` branches of `DateField` and `TimeField`, render picker-compatible input types and pass canonical ISO values directly to callbacks. Preserve `DateTimePicker` branches for iOS and Android.

6. Extend `tests/client.test.ts` for friendly timezone labels. Update `tests/e2e/workflows.spec.ts` to prove cancellation confirmation disappears after a successful save, cancelled rows do not display competing status text, friendly timezone labels render, and web date/time inputs retain their input types.

- No backend contract, storage, or deployment changes.
- No date/time picker dependency is added; Expo’s installed native picker remains the native implementation.
- No change to persisted time zone values or Luxon time-zone calculations.
